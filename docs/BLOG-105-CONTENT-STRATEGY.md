## 5. How each draft is produced (quality bar)

**Workflow (uses the existing system; nothing parallel is built):**
1. Draft written as `scripts/blog-content/<slug>.html` plus its metadata entry in `scripts/seed-blogs.mjs` (focus keyword, secondary keywords, SEO title ≤ 60, description ≤ 160, excerpt, category, tags, image + alt).
2. `node --env-file=.env.local scripts/seed-blogs.mjs --dry-run --only=<batch slugs>` validates word count, title/description length, no H1, no inline styles, and that internal links point at real pages.
3. **Management review of the files** (PR on a branch) for financial accuracy, claims and tone. Each draft carries a review box listing every figure and its source.
4. After approval: `seed-blogs.mjs --new-as=draft --only=<approved slugs>` writes them to the database as **draft** (not public, not in the sitemap). This writes to the **production database**, so it runs only with your go-ahead.
5. In admin, a reviewer moves each post draft → pending; an **admin** approves → published. The status API is admin-only for approval, and runs its SEO checks on publish. Publishing triggers sitemap revalidation automatically.
6. After publishing: `seo-crawl.mjs` check (200, in sitemap, one H1, BlogPosting, alt text, ≥ 1 inbound link) and URL Inspection in GSC. Status tracking: the tracker in `STAGE-2-IMPLEMENTATION-PLAN.md` §6.

**Fixes needed in the seeder before Batch 1** (small, script-only, part of the Stage 2 plan):
- `--new-as` currently **defaults to `published`**. Change the default to `draft`, so a forgotten flag can never publish.
- `SITE_PAGES` is missing **`/used-car-loan`**, so the validator would reject links to it. Add it.
- Add a check that rejects a `focusKeyword` already used by another post (cannibalisation guard).

**Every article:**
- One H1 (the template renders the title); H2/H3 hierarchy; 1,000–1,500 words **only where the topic needs it**. Comparisons and processes may be shorter, and no filler is added to hit a count.
- Primary keyword in title, first paragraph and one H2, naturally; secondary keywords as they fit. No city stuffing.
- **Financial content safety:** no rate, fee, amount, LTV, timeline, approval odds or lender name unless it is already on `/loan-disclosure` or approved in `CLAIMS-MANAGEMENT-REVIEW.md`. Worked examples are labelled *illustrative*. EzyLoan is described as a facilitator, never a lender.
- Internal links: the owner service page (descriptive anchor), 1–3 related posts, `/emi-calculator` where useful. The template also adds the topic-cluster block automatically.
- External references only to primary sources: RBI (e.g. the Key Fact Statement directions), Parivahan/Vahan, the Odisha Transport Department, CIBIL/TransUnion. Each reference is verified at drafting time and dated.
- **FAQ:** written as plain HTML questions and answers. **No FAQPage schema on blogs**: since Aug 2023 Google shows FAQ rich results only for well-known government and health sites, so the markup would not be eligible. The blog template already emits BlogPosting + BreadcrumbList with author, dates and canonical.
- Featured image: relevant, licence-clear (Unsplash, as now, or EzyLoan's own photos), with descriptive alt text.
- Author: "EzyLoan Editorial Team" (Organization) unless management names a real, consenting reviewer. Never an invented person.
